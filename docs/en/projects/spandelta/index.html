Case study / Observability

SpanDelta.

I compare traces across two releases and follow a regression down to an individual request.

Technology

KotlinOpenTelemetrySQLiteMCP

The problem

When checkout slows down after a change, total request time gives few clues about where to look. A reviewer needs to compare the same operations and inspect a request that actually experienced the delay.

How it works

SpanDelta groups OpenTelemetry spans by service and operation, compares p95 latency and error rates, and keeps trace IDs in SQLite. CI can use the comparison as a release gate. An agent can inspect the same data through MCP.

Inside the example

In the synthetic example, each release handles 40 requests. Checkout p95 climbs from 151 to 231 ms. Payment authorization moves from 89 to 169 ms, while inventory reservation stays at 48 ms. The report points to a candidate request for investigating the payment path.

Limits of the analysis

The comparison depends on similar traffic and sampling. Confirming the cause of a delay still requires inspecting the trace and the code that handled that operation.
