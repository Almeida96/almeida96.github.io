ToolTape.

I record an agent's tool calls to replay the responses and review changes to an MCP server.

Project example

Engineering details

MCP recording
A Java 21 CLI launches a local MCP server, discovers its tools and records the requested calls over standard input and output. Jackson parses the JSON exchanged by the two processes.
Replay semantics
The replay server consumes one recorded exchange per matching call. Repeated calls can return different recorded outcomes. A request sent out of sequence leaves the next exchange available for retry.
Integrity and testing
Each recording carries a SHA-256 checksum over canonical JSON. JUnit tests cover edited recordings, missing versus null fields, reordered arrays and timeouts that must terminate the child process.

The problem

An agent test can fail because a service returns different data on the next run. Reproducing the failure requires the arguments, responses and call order that the agent saw.

How it works

ToolTape records a sequence of MCP calls and preserves their results and errors in a JSON file. A local server replays that session. Comparing two recordings produces a report with the path to each changed field.

Inside the example

In the synthetic support-ticket demo, two recordings of the same three calls produce six differences. Ticket INC-1042 changes priority from P2 to P1 and status from investigating to resolved. The report points to both values in the original recordings.

Limits of the analysis

Replay follows the recorded order and arguments. An agent that chooses another tool or sequence needs its own scenario.
