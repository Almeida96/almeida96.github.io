PatchMeter.

I match added lines in a diff to coverage records to show exactly what the tests left unexecuted.

The problem

A small patch can introduce an untested business rule and barely move a project's overall coverage. During review, I want to know which line changed and what the test report actually recorded for it.

How it works

PatchMeter matches each added Git line by path and line number against JaCoCo or LCOV records. It distinguishes execution, zero execution and missing data. Three MCP queries let a reviewer inspect the results by file and line.

Inside the example

The synthetic example adds a quantity discount. Of four added Java lines, two ran, the discount on line 7 recorded zero execution and line 8 had no record. Observed coverage comes to 66.6667%, below the 80% threshold.

Limits of the analysis

The diff and coverage report must come from the same revision. The percentage counts lines with explicit records. Reviewers still need to check what the test assertions say about the discount.
