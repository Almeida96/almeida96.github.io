Case study / Queue recovery

QueueSift.

I built QueueSift to answer a question that comes up after a queue consumer recovers. Which failed deliveries can we consider sending again?

Engineering details

Transactional imports
A Kotlin CLI on Java 21 imports messages, processing receipts and optional checkpoints into SQLite in one transaction. It stores source line numbers and SHA-256 hashes so reviewers can locate the input behind a decision.
Identity and ordering
The recovery engine groups deliveries by tenant and event ID. Conflicting payloads put every copy on hold. For an ordered stream, a missing sequence number blocks later candidates until the gap is resolved.
Agent access and tests
A read-only MCP server exposes the decisions and their evidence. JUnit tests check that collection queries omit message payloads and that inspecting a payload requires explicit permission at server startup.

The problem

A timeout can land an order in a dead-letter queue after its reservation has already succeeded. Replaying every delivery could reserve stock twice. An operator needs the original event, the consumer’s processing receipts and a way to spot conflicting copies.

How it works

QueueSift imports a queue export and processing receipts into a local SQLite ledger. A policy describes the consumer’s idempotency and the failures an operator has marked as resolved. The CLI proposes batches for review. An agent can use read-only MCP tools to trace a decision back to a policy rule and the exact input lines.

Inside the example

The synthetic fulfillment demo evaluates the same 16 deliveries twice. While the dependency timeout is unresolved, none qualify for review. Once the policy marks it resolved, the report proposes two batches. The first contains m01 and m13. Both have event ID evt-1, but they belong to different tenants. The second contains m14.

Limits of the analysis

The demo has partial receipt coverage, so a missing receipt leaves the processing outcome unknown. Before sending anything, an operator still has to check the live consumer state and confirm how it handles duplicates. QueueSift stops at the review manifest.

Run the example

With Java 21 installed, extract the release ZIP and run this command from the extracted folder. Open fulfillment-review/recovery/report.html to inspect the result.

bin/queuesift demo --out fulfillment-review

On Windows, use .\bin\queuesift.bat in place of bin/queuesift.
