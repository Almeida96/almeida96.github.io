MedApp.

Um paciente que retorna toda semana precisa de horários que caibam na agenda do consultório. No MedApp, o profissional confere a série inteira antes de incluí-la no calendário.

Protótipo móvel

Detalhes técnicos ↓

Detalhes técnicos.

O servidor verifica as datas propostas contra consultas e bloqueios existentes e grava a série de uma só vez. Um conflito na última data impede que parte da série fique agendada por engano.

Cliente e API

O aplicativo usa TypeScript, React Native e Expo. Uma API em JavaScript, construída com Node.js, atende às requisições da agenda. No aparelho, o Expo SecureStore guarda o token de sessão usado nas requisições autenticadas.

Modelo de persistência

O protótipo usa um processo de API e um arquivo JSON. As gravações entram em uma fila, alteram uma cópia dos dados e substituem o arquivo antes que o novo estado fique visível para outras requisições.

Repetição de agendamentos

Cada pedido de agendamento recorrente recebe um identificador. Repetir o mesmo pedido devolve a série já salva, inclusive após reiniciar a API. Reutilizar o identificador com datas ou regras diferentes gera um conflito HTTP 409.

Testes da agenda

Os testes em Node.js disputam os mesmos horários com duas séries e introduzem um conflito em uma consulta posterior. Também verificam a mudança do horário de verão, quando uma hora local deixa de existir.

Passo a passo

  1. Abra a agenda e selecione o paciente para o agendamento recorrente.
  2. Escolha o dia, o horário e a quantidade de consultas, depois confira as datas propostas.
  3. Resolva eventuais conflitos, confirme a série e consulte os horários na visão semanal.

Estágio de desenvolvimento

O protótipo móvel funciona com uma API local e tem prévia no navegador. As versões assinadas e a validação em aparelhos físicos ainda estão pendentes.
