React Native · Expo

MedApp.

A patient who returns every week needs a sequence of appointments that fits around the rest of the clinic’s schedule. MedApp lets the clinician check the whole series before adding it to the calendar.

Mobile prototype

Engineering details ↓

Engineering details

The server checks the proposed visits against existing appointments and blocked hours. It saves the series together so a conflict on the last date cannot leave half a schedule booked.

Client and API
The mobile client uses TypeScript, React Native and Expo. A JavaScript API built on Node.js handles calendar requests. On the device, Expo SecureStore holds the session token used for authenticated requests.
Persistence model
The prototype runs a single API process backed by a JSON file. Writes enter a queue, update a copy of the state and replace the file before the new state becomes visible to other requests.
Safe booking retries
A recurring booking carries a request ID. Retrying the same request returns the existing series, even after a restart. Reusing its ID with different dates or rules produces an HTTP 409 conflict.
Calendar tests
Node.js tests submit two series competing for the same slots and introduce a conflict on a later visit. Other cases exercise daylight saving transitions, when a requested local time can disappear from the calendar.

A walkthrough

  1. Open the calendar and choose a patient for a recurring appointment.
  2. Set the day, time and number of visits, then check the proposed dates.
  3. Resolve any conflicts, confirm the series and review the bookings in the weekly calendar.

Development status

The mobile prototype works with a local API and has a browser preview. Signed mobile builds and validation on physical devices are pending.
